Rules & Governance
How the organization operates — hierarchy, briefings, error learning

Organizational Hierarchy

1 Every Agent Has Their Own Space

Each agent operates in its own department directory. SCRIBE writes in departments/content/. LENS writes in departments/social/. No agent touches another agent's output files directly. Clean separation of concerns.

2 The Boss is the Orchestrator

The Boss (you) doesn't do the work — you make decisions. Every agent briefs you via Telegram. Standups at 06:00, retros at 20:00, board meetings Monday. You approve, redirect, or override. The org moves based on your decisions.

3 Meetings Are for Synchronization

Morning standup = everyone reports status. Evening retro = what shipped, what failed. Board meeting = strategic direction. These exist so the Boss has full situational awareness and agents stay aligned. No meeting, no coordination.

4 Chain of Command

Boss → CHIEF (Chief of Staff) → VP Content / VP Growth / VP Operations → Department agents. Issues escalate UP the chain. Decisions flow DOWN. CHIEF is the central coordinator who reads all department states and compiles the big picture.

5 Learn From Every Error

Every failure gets logged in state/incident-log.json with a post-mortem. CHIEF reads incidents in every standup. SENTINEL flags overnight failures. The org doesn't repeat mistakes — the incident log IS the institutional memory. If it happened before, there's a record.

6 Boss Gets Briefed — Always

06:00 — Morning standup (what's planned today). 07:00 — Daily Telegram summary. 15:00 — Blog status report. 20:00 — Evening retro (what shipped). Monday — Board meeting (strategy). Friday — Weekly report (KPIs). The Boss is never in the dark.

7 Nothing Ships Without Quality Gates

Blogs pass 25-check QA. Image prompts pass 17-check QA. All customer-facing actions require approval. No agent can push directly to customers. The queue is the chokepoint — everything flows through it.

8 Shifts Operate Like a Real Business

Morning shift = CREATE (content, designs, campaigns). Afternoon shift = SELL (calls, engagement, conversions). Night shift = MONITOR (health checks, incident detection). Every shift has a lead. Handoff notes are mandatory. No dead time.

9 Scale by Adding Agents, Not Complexity

New capability = new agent with its own prompt, schedule, and output directory. Plugs into existing data flow. Doesn't change other agents. The team grows by specialization, not by making existing agents do more.

10 State is the Single Source of Truth

Agents don't talk to each other. They read and write JSON state files. daily-standup.json, queue.json, incident-log.json — these are the shared brain. Every run commits to Git. Full audit trail. If it's not in state, it didn't happen.

Error Learning Protocol

When Something Fails

1. Logged immediately in state/incident-log.json with timestamp, department, error, and severity.
2. SENTINEL detects in next health check (or immediately if during night shift).
3. CHIEF includes in next standup/retro briefing.
4. Post-mortem: what happened, why, what prevents recurrence.
5. All agents read the standup — they learn from every org-wide failure.
